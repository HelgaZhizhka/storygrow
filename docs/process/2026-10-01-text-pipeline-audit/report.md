## Как пишет приложение

1. **Plan**, по умолчанию GPT-4o: цель/описание, герой, возраст, арка, каталог шаблонов, пример. Модель сразу создаёт сюжет по страницам, Visual Bible, мораль и пять вопросов.
2. Мир ограничен маленькими бытовыми ситуациями дошкольника. Prompt исключает случайное волшебство и приключения за пределами обычного дня. Интересы ребёнка — мягкие детали, не повод менять конфликт и урок.
3. Добродетель 5–6: знакомство → испытание → внутреннее затруднение → попытка → успех → закрепление. Порок 5–6: недостаток → плохой поступок → внешнее последствие → осознание → исправление → заслуженная развязка. Для 3–4 предусмотрена добродетель, не порок.
4. **Prose**, по умолчанию GPT-5: готовый план и ещё один выбранный пример. Прямые инструкции: “in the tradition of В. Сутеев and the Russian folk tale”, “warm Сутеев read-aloud”. Нельзя перестраивать историю, менять страницы и вводить предметы вне кадра. Имя героя на каждой странице, 2–3 предложения примерно на три четверти лимита. Мораль один раз в финале.
5. **Название** — дополнительный вызов GPT-4o по умолчанию. Конкретное игровое название с именем героя и сутеевским ориентиром. Запреты/три попытки не проверяют естественность; после исчерпания попыток допускается последний кандидат.
6. **Проверка**: структура/язык и judge GPT-4o-mini по умолчанию; регистр также оценивается с примерами. Порог registerMatch по умолчанию 7, отдельных guardrails 6. Vocabulary-RAG не передаётся автору как обязательный словарь.
7. При непрохождении возможны две повторные попытки всего пути с замечаниями, то есть до трёх генераций; сохраняются StoryEval. Этот механизм действительно влияет на выбор итоговой прозы приложения.
8. Затем storyJson, картинки xAI/Visual Bible/image-judge и PDF. Повтор картинок использует сохранённый текст, не редактирует его.

Модели и число повторов здесь — defaults кода. Runtime env всех сервисов не проверялся. Константа STORY_MODEL=gpt-4o сама по себе не означает, что нынешний Prose использует GPT-4o.

### Золотые примеры

В exemplars.ts девять текстов: шесть для 5–6, три для 3–4. Это встроенные ориентиры, не индивидуальный шаблон каждой цели и не корпус произведений Сутеева.

Подбор по цели/арке/возрасту; без точного совпадения — случайный пример той же арки/возраста. Доброта/Сочувствие/Забота о младших делят «Соня и новенький»; Самостоятельность/Настойчивость/Трудолюбие — общий пример самостоятельности. Пользовательская цель получает fallback.

Plan и Prose выбирают пример отдельно. Нет доказанной памяти прошлых книг ребёнка и гарантии разнообразия. Наши «Прятки», «Красная варежка» и «Почтовый ящик» не добавлены в продуктовый каталог.

Полные точные инструкции: [current-instructions.md](current-instructions.md), механически скопированы из замороженного запроса.

2. Автор GPT-5-2025-08-07. System: литературное ядро + неизменённая граница безопасности. User: Алиса 6, описание цели, добродетель, слушатель 5–6, 350–550 слов.
3. Один вызов придумывает сюжет, название и весь текст, возвращает JSON title/paragraphs. Нет готового замысла, примеров, Сутеева, Visual Bible, страниц, редактора и отдельного вызова названия.
4. Код проверяет слова, латиницу и отдельные шаблоны названия. Не проверяет грамматику, движения персонажей, логику предметов, интерес или темп.
5. Отдельный GPT-4o-2024-08-06 читает готовую историю только на безопасность. Pass/fail; текст не меняет. Нет литературного judge и повторов.

## Установленные причины и границы знания

Старый продукт ограничивают бытовой мир, фиксированные биты, немногочисленные общие примеры, короткие страницы, кадры и подражание регистру. Это основания подозревать однообразие, не доказательство причины каждого плохого текста.

Последние тексты имеют конкретные дефекты: «резиновая мячик»; неясная вина Тимы, решение не устраняет ясно причину падения; флаг меняет положение без перехода. В спектакле технические замены вытесняют событие; обещанный выход Кота не доведён; механизм занавеса непонятен; диалоги содержат «без лазания и без булавок», «Если без опасности — пробуй».

Не установлено, что safety вызвала все дефекты, что другая модель гарантирует качество или ещё более короткий prompt/планировщик решит проблему. Сутеева, страницы и литературный judge уже убрали в последних запросах, качество не стало приемлемым. Последующий safety-check не переписывает прозу; ограничения в system могли повлиять, но причинный эффект не измерен.
