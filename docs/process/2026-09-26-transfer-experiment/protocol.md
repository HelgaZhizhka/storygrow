# STO-15 — проверка переноса редакционных принципов

Обновление 2026-09-27: **опыт выполнен**, [результаты и ограничения](report.md), [полный журнал](evidence.jsonl). Литературная проверка не пройдена. Ниже сохранён протокол подготовки и его предзапускное уточнение.

Исторический статус 2026-09-26: **подготовлено, не запущено**. Владелец поручила работу локальному Codex самостоятельно, без Claude. Текущий завершённый объём — сохранение «Красной варежки», конкретный вариант опыта и оценка стоимости; новых платных вызовов не было. Это документация будущего исследовательского запуска, не подключённый код и не изменение production.

## Что проверяем

Может ли прежний автор с новой краткой литературной инструкцией самостоятельно придумать и написать три разных связных истории, где каталожная цель влияет на исход? Без готового замысла, полного текста-образца и редактора после генерации.

Три случая: Доброта, Настойчивость, Самостоятельность; Алиса, 6 лет; 5–6 / virtue; 350–550 слов. Названия и описания целей взяты из `backend/src/scripts/lib/learning-goals.data.ts` при подготовке. Третий случай не имеет нашего положительного текстового примера. Это перенос на другую каталожную цель, не проверка пользовательских целей, 3–4, flaw или повторяемости на большой выборке.

## Конкретный вход

- [author-core.md](author-core.md) — литературная инструкция для чтения человеком.
- [requests.json](requests.json) — три полных system/user запроса, параметры и fingerprint, подготовленные без API. System = core + дословный SAFETY_BOUNDARY из текущего whole-story.prompt.ts. Safety hash зафиксирован.
- `WholeStorySchema`, `generateObject`, детерминированные `runTextGates` и отдельные `StorySafetySchema`/`STORY_SAFETY_SYSTEM` остаются прежними. Перед запуском фиксируются точный Git SHA и хеши всех зависимостей; при изменении любого входа — новая версия manifest, а не смешивание результатов.
- Не передаём «Прятки», «Красную варежку», архив занятий, старые exemplars, планы, готовые сюжеты, образцовые названия или декорации. Не подсказываем запретом конкретные отвергнутые сюжеты; сходство с ними проверяем при чтении.
- Возрастные/постраничные слоты, заданное число попыток, требование много диалогов, ссылка на Сутеева и обязательное трудное самопожертвование не входят в литературное ядро. Арка добродетели сохранена: решение Алисы должно влиять на исход.

Это пакет изменений литературного задания, **не однофакторный A/B-тест**. Старые результаты — исторический фон. Даже три удачных ответа не докажут, что эффект вызвало удаление Сутеева или что задача решена для production.

## Исполнение следующего запуска

Использовать исследовательский отдельный runner по образцу `../2026-09-25-author-study/runner.cjs`, не менять существующий замороженный runner и его результаты. Новый runner ещё не реализован. Перед его использованием проверить: prepare не вызывает сеть; существующая отметка run-started запрещает повтор; ошибка не порождает retries; размер входа проверяется до запроса; сырой ответ сохраняется до проверки качества. Реальный запуск требует адаптации и этих проверок; `requests.json` сам по себе ничего не запускает.

1. Проверить доступность точных моделей, LangFuse health и авторизованное чтение traces. Не переключать модель молча. На официальной странице GPT-5 snapshot помечен Deprecated: это не доказательство недоступности аккаунту, но доступность должна быть подтверждена до опыта. При недоступности — остановиться и записать причину; пересмотреть модель и стоимость отдельно.
2. Использовать ConfigService для секретов, тот же standard service tier и настройки из manifest. Температура/reasoning effort не задаются явно, как в прошлом опыте. Не пытаться передавать неподдерживаемую температуру.
3. Ровно один авторский вызов на случай, без автоматических исправлений, максимум три. Каждый имеет LangFuse trace, request, response, resolved model, usage, finish reason, latency и статус ошибки. При провале схемы или обрыве сохранить доступный сырой ответ/usage; не восстанавливать текст руками и не повторять скрытно. Техническая ошибка прекращает оставшиеся вызовы.
4. Для каждого успешно разобранного текста — прежние гейты и один safety-вызов; максимум три. Safety fail/error не публикуется как безопасная книга. Сохраняем и неудачные результаты как исследовательские данные. Числовой craft-judge не вызываем: он раньше давал ложную уверенность и здесь не заменяет чтение.
5. Сохранить неизменённые ответы, полный manifest и trace IDs. После flush получить traces обратно по API, сопоставить GENERATION model/usage/cost. Без получения traces обратно не заявлять подтверждённый расход. Нет Book/StoryEval, иллюстраций, PDF или product-integration claim.
6. Прочитать все три текста и записать конкретные дефекты до любых правок; не выбирать один удачный вместо отчёта обо всех трёх. Первый проход — только тексты, второй — с целью. Это не независимая или слепая оценка: Codex знает протокол и создал prompt.

Локальная инфраструктура: прошлый обычный compose конфликтовал с чужими портами 5432/6379. Прочитать handoff и проверить текущее состояние контейнеров. Использовать исследовательский override только при необходимости; не трогать контейнеры другого проекта. Остановить после работы только запущенные нами сервисы, если они никому не нужны.

## Рубрика до чтения

Для каждого критерия: «да / частично / нет» + место в тексте, которое обосновывает вывод. Не складывать в красивую итоговую цифру.

| Критерий | Что проверять |
| --- | --- |
| Интерес | Чего хочет героиня, что мешает, какой исход читатель ждёт? Субъективный редакторский вывод, не измерение интереса детей. |
| Последовательность | Проследить каждого участника и важный предмет между действиями, в том числе внутри сцены. Нет внезапных возвращений и исчезновений. |
| Причинность | Почему произошёл поворот, откуда взялось решение? Нет подаренного автором результата без подготовки. |
| Главная героиня | Собственное решение Алисы существенно; помощник не выполняет за неё всю работу. |
| Цель | Назвать поступок и его последствие. Если убрать этот поступок, меняется ли исход? Настойчивость: новая попытка/подход после неудачи, не просто случайная находка. Самостоятельность: собственная посильная задача, не отказ от взрослых. |
| Язык и название | Понятно при чтении вслух, ясны реплики, нет вычурных метафор и взрослой морали. Название связано с событием/предметом. |
| Развязка | Показан результат, а не только решение попробовать или обещание измениться. |
| Разнообразие | Сравнить желания, конфликты, действия и развязки всех трёх. Смена имён, места или предмета при том же ходе не считается новым сюжетом. |

Вердикт: «отвергнуть», «нужна существенная редактура», «кандидат для чтения владельцем». Существенная редактура = изменение причины конфликта, мотивации, последовательности или развязки; её нельзя скрыть под исправлением пары слов. Кандидат не равен принятому владельцем gold.

Условие продолжения: все три проходят технические проверки, не требуют существенной редакторской переделки, не повторяют один сюжет. Иначе общий вывод — инструкция пока не прошла маленькую проверку, с указанием всех дефектов. Даже успех только разрешает более широкую проверку, не внедрение без остальных ворот spec/ADR-0008.

## Вопросы для рефлексии

В сохранённых редакционных примерах три вопроса остаются после истории. Текущая WholeStorySchema вопросов не содержит; не дописываем их незаметно в авторский ответ и не выдаём ручные вопросы за результат генерации. Здесь измеряем только качество самой истории. После принятия нового текста — отдельно проверить генерацию вопросов по его неизменённому содержимому: причина поступка, действие/последствие, открытый перенос на опыт ребёнка. Число и интеграцию согласовать со схемой продукта (действующая Story содержит пять discussionQuestions); в этом опыте схему не меняем. Вопросы не должны исправлять непонятную цель или незавершённый сюжет.

## Стоимость

Официальные тарифы проверены 2026-09-26: [GPT-5](https://developers.openai.com/api/docs/models/gpt-5) — $1.25/M input и $10/M output; [GPT-4o](https://developers.openai.com/api/docs/models/gpt-4o) — $2.50/M input и $10/M output. Не учитываем скидку кеша, не используем инструменты с отдельной оплатой. Reasoning учитывается в выходном лимите/usage, не добавляется второй раз.

При обязательном предзапросном ограничении полного входа (включая схему и служебное обрамление) до 4000 токенов на автора и 6000 на safety:

- Автор: 3 × (4000 × 1.25 + 10000 × 10) / 1 000 000 = $0.315.
- Safety: 3 × (6000 × 2.50 + 2000 × 10) / 1 000 000 = $0.105.
- Расчётный максимум этих шести запросов — $0.42, резерв до $0.50. Это условная граница по тарифам и лимитам, не уже действующий ограничитель: runner должен реализовать и проверить контроль размера полного запроса до запуска. Если точный размер нельзя подтвердить, взять консервативную верхнюю оценку или пересчитать бюджет до запроса.
- Вероятный расход около $0.12–0.20 по прошлым usage; это прогноз, не обещание. Фактический расход будущего опыта — по traces. Расход на новые API-вызовы в этой подготовке: $0, вызовов 0.

## Что уже готово и что осталось

Готовы: сохранённый редакционный пример, проверка его событий, точные три запроса с неизменённой safety-границей, заранее записанная рубрика, пределы выводов и расчёт стоимости. Не готовы: отдельный исполняемый runner, его preflight-проверки, live outputs и оценка реального качества. Production и текущий harness не менялись. Следующая работа — реализовать ограниченный исследовательский запуск и выполнить три случая; не писать ещё одну ручную сказку вместо проверки генератора.

## Исполнение 2026-09-27 — обновление до первого вызова

Владелец попросила продолжить работу. Реализован отдельный `runner.cjs`, подготовка/offline self-test проверены без сетевых вызовов. Перед запуском действуют шесть вызовов без retries и общий резерв $0.50. Вместо неподтверждённых лимитов входа 4000/6000 используются реальные сериализованные SDK-запросы: перед отправкой берётся консервативная оценка входа по UTF-8 байтам всего JSON + 1024 токена запаса на служебное обрамление; к ней прибавляется полный выходной лимит по тарифу. Вызов запрещён, если вместе с уже учтённым uncached usage он превышает $0.50. Это консервативная оценка для byte-level токенизации, не счётчик токенов API и не гарантия биллинга. После каждого ответа учёт сверяется по usage; неизвестный usage или техническая ошибка прекращают запуск. При ошибке сохраняются доступные response/usage и сырой HTTP-ответ; повтор не выполняется. Предыдущие $0.42 остаются условным расчётом, не реализованным жёстким пределом. Offline-проверки блокируют неизвестную модель, превышение выходного лимита, чрезмерный вход и превышение остатка бюджета. Подготовка не инициализирует SDK/ключи/сеть.

Каталог и литературная инструкция не изменены. GPT-5 snapshot проверяется через read-only Models API до генерации. Результаты сохраняются в `backend/output/whole-story/2026-09-27-transfer/`; полный evidence архив и редакторское чтение добавляются после завершения. Запуск не использует CLI/автоматические задачи Claude или другие агенты.
